# PRD：walkthrough skill

## 問題

看得懂教學，不代表講得清楚自己的專案。面試被問「這段為什麼這樣寫」「這個數字怎麼來的」時，需要的是對自己程式的理解；而一般的 AI 教學會憑印象寫數字、行號容易對不上，也沒有複習機制，讀完很快就忘了。

## 使用者

想真正弄懂並講清楚自己程式的人，程式可以是資料分析、後端、前端或系統架構。

## 要做到

- 逐行講解自己的程式，每一步顯示實際執行當下的資料、輸出或畫面。
- 先審查並修好程式，教的是正確的版本；修改前的問題變成教材和面試素材。
- 用學習者已經會的東西來解釋新觀念（設定在 `~/learning/PROFILE.md`）。
- 產生複習卡，在一個複習中心用間隔重複複習所有專案；程式類以填空題為主。
- 每份教材都能自我檢查：行號、引用的程式碼、填空答案都和原始檔一致。

## 不做

- 學一個全新的主題（那是 Matt Pocock 的 `teach` 這類 skill 的事；這裡只講使用者已有的程式）。
- 雲端同步複習進度、多人共用。
- 把個人學習資料（背景設定、學習紀錄、複習卡）放進公開 repo。

## 怎樣算成功

- 教材上每個數字都能追到一次實際執行；`verify` 沒有任何問題。
- 程式改版後，重跑擷取和產生頁面就能更新，不需要手動改行號。
- 使用者能不看教材，回答各章的面試題和複習卡。
